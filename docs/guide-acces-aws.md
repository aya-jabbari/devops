# Guide : accès de l'équipe au compte AWS

Pour : **Maryam** (propriétaire du compte AWS), puis chaque membre. Durée : environ 30 minutes.
Objectif : que chacune travaille avec **son propre utilisateur IAM**, jamais avec le compte racine ni la clé d'une autre,
et qu'Aya puisse lancer Terraform et lire la facturation pour le rapport de coûts.

> Règle absolue : aucun mot de passe, clé d'accès, ID de clé ni fichier `.csv` d'identifiants dans Git, une issue,
> une PR ou un message de groupe. Les secrets se transmettent en privé (gestionnaire de mots de passe ou de vive voix).

## Partie A : Maryam, avec le compte racine

### A1. Activer la MFA sur le compte racine

Menu en haut à droite (nom du compte), **Security credentials**, **Multi-factor authentication (MFA)**,
**Assign MFA device**, puis **Authenticator app**, et scanner le QR code avec une application d'authentification
(Google Authenticator, Microsoft Authenticator, Authy…). Saisir deux codes consécutifs pour valider.

### A2. Autoriser les utilisateurs IAM à voir la facturation

Sans cette étape, même un utilisateur avec la bonne politique voit « Access denied » sur la facturation.

Menu du compte, **Account**, section **IAM user and role access to Billing information**, **Edit**,
cocher **Activate IAM Access**, **Update**.

### A3. Relever les crédits

**Billing and Cost Management**, **Credits** : noter le montant restant, la **date d'expiration** et les services couverts
(vérifier que EC2 en fait partie). Sur l'offre gratuite (Free plan), noter aussi la date de fin de l'offre : à cette date
le compte doit passer en offre payante, sinon il est fermé avec ses ressources.

### A4. Créer un budget

**Billing and Cost Management**, **Budgets**, **Create budget** :

1. **Use a template**, modèle **Monthly cost budget**.
2. Nom : `supportops-monthly`. Montant : **10 $**.
3. E-mails destinataires : les adresses des trois membres.
4. **Create budget**.

Ajouter ensuite, dans le budget, des seuils d'alerte à 50 % et 80 % (onglet **Alerts**, **Edit**), en coût réel.
Dans **Billing preferences**, activer aussi **Receive Free Tier usage alerts**.

### A5. Vérifier le quota EC2 dans la région Paris

Choisir la région **Europe (Paris) eu-west-3** en haut à droite. **Service Quotas**, **Amazon Elastic Compute Cloud (Amazon EC2)**,
rechercher **Running On-Demand Standard (A, C, D, H, I, M, R, T, Z) instances**. La valeur doit être **au moins 2** (vCPU)
pour un `t3.medium`. Sinon, cliquer **Request increase** (délai possible pour un compte récent).

### A6. Créer la politique « gérer ses propres identifiants »

**IAM**, **Policies**, **Create policy**, onglet **JSON**, coller :

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ManageOwnKeysAndPassword",
      "Effect": "Allow",
      "Action": [
        "iam:GetUser", "iam:ChangePassword",
        "iam:CreateAccessKey", "iam:DeleteAccessKey", "iam:ListAccessKeys", "iam:UpdateAccessKey",
        "iam:ListMFADevices", "iam:EnableMFADevice", "iam:ResyncMFADevice"
      ],
      "Resource": "arn:aws:iam::*:user/${aws:username}"
    },
    {
      "Sid": "CreateOwnVirtualMFA",
      "Effect": "Allow",
      "Action": "iam:CreateVirtualMFADevice",
      "Resource": "arn:aws:iam::*:mfa/*"
    }
  ]
}
```

**Next**, nom : `SupportOpsSelfManageCredentials`, **Create policy**.

`${aws:username}` limite chaque personne à **ses propres** clés : personne ne peut créer de clé pour une autre.

### A7. Créer le groupe de l'équipe

**IAM**, **User groups**, **Create group**. Nom : `supportops-team`. Attacher ces politiques :

| Politique | Pourquoi |
|---|---|
| `AmazonEC2FullAccess` | Terraform : instance, IP élastique, groupe de sécurité, clé SSH |
| `AmazonVPCFullAccess` | Terraform : VPC, sous-réseau, passerelle, routes |
| `IAMUserChangePassword` | Changer le mot de passe temporaire à la première connexion |
| `AWSBillingReadOnlyAccess` | Lire les coûts pour le rapport de coûts |
| `SupportOpsSelfManageCredentials` | Créer sa propre clé d'accès et sa MFA (A6) |

**Create user group**.

### A8. Créer un utilisateur par membre

À faire trois fois : `aya`, `doha`, `maryam` (Maryam aussi, pour ne plus utiliser le compte racine au quotidien).

**IAM**, **Users**, **Create user** :

1. Nom : `aya` (puis `doha`, `maryam`).
2. Cocher **Provide user access to the AWS Management Console**, choisir **I want to create an IAM user**.
3. Mot de passe : **Autogenerated password**, et laisser coché **Users must create a new password at next sign-in**.
4. **Next**, **Add user to group**, cocher `supportops-team`.
5. **Next**, **Create user**. Sur la page finale, noter le mot de passe (ou **Download .csv file**) **puis supprimer le .csv**
   une fois transmis.

### A9. Récupérer l'URL de connexion

**IAM**, **Dashboard**, panneau **AWS Account** : **Account ID** (12 chiffres) et **Sign-in URL for IAM users**
(`https://<account-id>.signin.aws.amazon.com/console`). On peut créer un alias (`supportops-equipe`) pour une URL plus lisible.

### A10. Transmettre à chaque membre

| Info | Canal |
|---|---|
| URL de connexion et nom d'utilisateur | Message privé |
| Mot de passe temporaire | **Autre** canal privé, ou de vive voix |
| Crédits (montant, expiration), région `eu-west-3` | Peut aller dans le groupe de l'équipe |

Ensuite, Maryam se déconnecte du compte racine et utilise son utilisateur `maryam`.

## Partie B : chaque membre, avec son utilisateur IAM

1. Se connecter avec l'URL IAM, le nom d'utilisateur et le mot de passe temporaire, puis choisir un nouveau mot de passe.
2. **Activer sa MFA** : menu du compte, **Security credentials**, **Assign MFA device**, **Authenticator app**.
3. **Créer sa clé d'accès** (seulement si on lance Terraform) : **Security credentials**, **Create access key**,
   cas **Command Line Interface (CLI)**. Copier l'Access key ID et la Secret access key dans un gestionnaire de mots de passe :
   la clé secrète n'est affichée **qu'une fois**.
4. Dans WSL :

   ```bash
   aws configure --profile supportops      # clé, secret, région eu-west-3, format json
   export AWS_PROFILE=supportops
   aws sts get-caller-identity             # doit afficher ...:user/<votre-nom>
   ```

   Les identifiants sont stockés dans `~/.aws/credentials`, hors du dépôt.

## Qui lance quoi

L'état Terraform (`terraform.tfstate`) est **local, sur le poste d'Aya**. Un `terraform apply` lancé depuis un autre poste
ne connaît pas les ressources existantes et en créerait une deuxième série (double facture).

| Action | Qui |
|---|---|
| `terraform apply` et `terraform destroy` | **Aya uniquement** |
| `terraform plan` (contribution §5.3) | Maryam, avant le premier `apply` d'Aya, ou sur le poste d'Aya |
| Lecture des coûts | Les trois (facturation en lecture) |

Si plusieurs personnes doivent un jour appliquer, il faudra stocker l'état dans un bucket S3 partagé avec verrouillage.

## En cas de fuite d'une clé

1. **IAM**, **Users**, l'utilisateur concerné, **Security credentials**, clé concernée : **Deactivate** puis **Delete**.
2. Vérifier dans **EC2** (toutes les régions) qu'aucune instance inconnue ne tourne.
3. Créer une nouvelle clé et prévenir l'équipe.

- [ ] Politique `SupportOpsSelfManageCredentials` et groupe `supportops-team` (A6, A7)
- [ ] Utilisateurs `aya`, `doha`, `maryam` créés et transmis en privé (A8 à A10)
- [ ] Chaque membre : mot de passe changé, MFA activée (B1, B2)
- [ ] Aya : clé d'accès créée, `aws sts get-caller-identity` OK (B3, B4)
